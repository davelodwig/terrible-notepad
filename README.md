# terrible-notepad
Terrible Notepad, is a terrible system comprising of an awful api, a useless ui, and a frankly shocking database. It's deployment leaves a lot to be desired, and it's tests pass but sometimes not on purpose. 

**Used for training graduates and early careers members in what they might discover when joining new projects with existing codebases that have been running for a long time.**

## Introduction

After running many hackathons with new starters and graduates joining the consultancy world, we noticed a similar pattern, which is none of them had any experience working on brown field projects and existing code.  Instead by and large the opportunities we presented them with for training allowed them to build from the ground up.  In reality this is unrealistic and these sorts of projects don't come along all that often.

With this in mind we built an absolutely terrible application.

You would be surprised how hard it is to build a terrible application but here it is, the API doesn't always do what you think, the UI is almost unusable, and the choice of components is sometimes strange.  And the less we talk about the database design the better to be honest.

## Puzzles

This system contains a number of puzzles, these range from simple bugs, to logic issues, to frankly downright absurd architectural choices.  There will be tests that never pass, and tests that always pass, and tests that it's not quite obvious what they are testing.

Your challenge as a team is to identify and fix as many of these puzzles as possible.  Points are awarded for each puzzle you solve, but beware the puzzle you just solved might actually be a genuine bug, you wouldn't believe how hard it is to write bad software.

## Development

This awful codebase is developed by a group of engineers in their free time in order to support the work they are doing on the early careers programme at CGI.  The code contains no client, company or confidential or IP of any kind.  

If you try to run this in production, then frankly you deserve to suffer.

### Challenges

It is remarkably hard to write bad software. Usually it builds up over years and years and years, so to aid this process we used quite a lot of AI assistance.  However AI is actually quite good these days and convincing the code assistant to write bad software is also quite hard.  Basically don't blame us if parts of this actually work as expected.
